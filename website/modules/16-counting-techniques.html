Where n choose k comes from

Send each permutation of 10 digits to the set of its first three entries. The set {3, 6, 7} is hit by 3! orders of the front times 7! orders of the back. Every set gets the same 3!·7!, so the number of 3-subsets is 10!/(3!·7!) = 120. In general this is the binomial coefficient C(n, k).

💡
Key Insight: Count something easy, then fix the relationship. A bijection keeps the count, a k-to-1 map divides by k, and an irregular map means you need a new recipe.
round_table.py 
def canonical(seating):
    return min(seating[i:] + seating[:i] for i in range(len(seating)))

for n in range(3, 7):
    tables = {canonical(p) for p in permutations(range(1, n + 1))}
    print(n, len(tables), factorial(n - 1))
Rotations are the same table, so pick one fixed rotation (the smallest) to stand for all of them.

Compare the brute-force count with (n−1)!. They match: 2, 6, 24, 120.

Counting with recipes: the two questions

1
Write a recipe

Four of a kind: pick a rank (13 ways), then any fifth card (48 ways).

2
Does it only build things in the set?

Yes: four cards of one rank plus a different card is always a four of a kind.

3
Is every object built exactly once?

Yes: the hand tells you its rank and its odd card. It is a bijection.

4
Multiply

13 · 48 = 624 four-of-a-kind hands.

⚠️
Common mistake: "Pick a pair, then any three cards" for at least one pair builds two-pair hands 2 ways and four-of-a-kinds 6 ways. The map is not k-to-1 for any single k, so no division can save it.
