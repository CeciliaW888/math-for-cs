Day 15 · Relations and Counting

Database tables, follower lists, and the ≤ sign all record which pairs of things are related. Today we give them one shared language. That language then hands us the main tool of the counting unit: matching one set up with another.

A relation is a set of arrows

A relation needs a domain, a codomain, and a set of pairs. You can classify it just by counting arrows.

1
Function: ≤ 1 arrow out of each input

Classes → professors is a function. Students → classes is not, because a student can take several classes.

2
Total: ≥ 1 arrow out of each input

1/x² from ℝ to ℝ isn't total, because 0 has no output. On ℝ∖{0}, the same pairs form a total function.

3
Injective / surjective: ≤ 1 / ≥ 1 arrow in

Injective means no output is hit twice. Surjective means every output is hit at least once.

4
All four: bijection

In a bijection, each input has exactly one arrow out and each output exactly one arrow in. So |A| = |B|.

Sameness vs order

A relation on a single set is just a digraph. If it is reflexive, symmetric, and transitive, it is an equivalence relation, which splits the set into blocks, like the ten remainder classes mod 10. If symmetry is replaced by antisymmetry, you get a weak partial order.

properties.py 

def properties(A, R):
    return {
        "reflexive": all((a, a) in R for a in A),
        "symmetric": all((b, a) in R for a, b in R),
        "antisymmetric": all(a == b for a, b in R if (b, a) in R),
        "transitive": all((a, d) in R for a, b in R for c, d in R if b == c),
    }
A relation is just a set of pairs, so each property becomes a check over those pairs.
Reflexive: every element must be related to itself.
Symmetric: every arrow needs a matching arrow going back.
Antisymmetric: arrows run both ways only from an element to itself.
Transitive: every two-step chain must already have a direct shortcut.
⚠️
Common mistake: "antisymmetric" doesn't mean "not symmetric". Equality is both symmetric and antisymmetric. The relation {(1,2), (2,1), (1,3)} is neither.

Counting with correspondences

A coat-check attendant never counts coats. One ticket per coat means the tickets handed out tell you the count. That idea is the bijection rule. Add the product rule ("and" multiplies) and the sum rule ("or" adds), and you can count a great deal.

💡
Generalized product rule: which cards are left changes with every draw, but how many are left (52, then 51, then 50, …) never depends on earlier choices. So a deck has 52! orderings.
