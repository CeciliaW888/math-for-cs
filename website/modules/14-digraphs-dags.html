Day 14 · Digraphs and DAGs

Build systems, course prerequisites, and spreadsheet formulas all form one-way dependency graphs. Today's maths answers two questions about them: in what order can you do the tasks, and how fast can a team finish them?

Arrows change everything

In a digraph, every vertex has an in-degree and an out-degree, and Σ in-degree = Σ out-degree = |E|. Reachability is no longer symmetric, so we group vertices into strongly connected components. Shrinking each one to a dot gives the condensation graph, which never contains a cycle.

ℹ️
Euler, directed: a digraph has an Euler tour exactly when it is strongly connected and every vertex has in-degree = out-degree. The undirected even-degree rule becomes "whatever comes in must go out".

Getting dressed is a DAG

A DAG models precedence constraints. A topological order lists every task before anything that depends on it. The recipe is simple: repeatedly do a source and cross it off.

The parallel speed limit

Picture a holiday dinner with plenty of cooks. Many dishes can cook side by side, but the gravy still has to wait for the roast. A schedule's span can never be smaller than the number of vertices on a longest path, and scheduling each vertex at its depth achieves exactly that number.

schedule.py 

preds = {t: [u for u, v in edges if v == t] for t in tasks}
depth = {}
def get_depth(v):
    # longest path ending at v; sources get 0
    if v not in depth:
        depth[v] = max((get_depth(u) + 1 for u in preds[v]), default=0)
    return depth[v]
rounds = {}
for t in tasks:
    rounds.setdefault(get_depth(t), []).append(t)
For each task, list the tasks that must come directly before it.
Remember depths once computed so no work is repeated.
A task can start only after its deepest prerequisite finishes.
With no prerequisites, start at time 0. Otherwise go one step after the latest prerequisite.
Group tasks by their depth. Each group is one parallel round.
On the dressing graph this prints four rounds, the length of the longest path.
💡
Chains vs antichains: the tasks in a single round form an antichain. The fewest antichains needed to cover a DAG equals the size of its largest chain. So the longest chain of dependencies, not the total amount of work, decides the finish time.
