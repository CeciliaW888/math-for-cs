Day 9 · Modular Arithmetic

Clocks, calendars, last digits, and hash tables all forget whole multiples and keep only the remainder. Today that habit becomes an arithmetic system.

We write a ≡ b (mod n) when n divides a − b. So 17 ≡ 12 ≡ 2 (mod 5). Each integer belongs to exactly one congruence class, named by its remainder.

⚠️
Notation trap: “a = b mod n” could mean the relation a ≡ b (mod n) or the function a = rem(b, n). And in code, Python gives -7 % 5 == 3 while C and JavaScript give −2.

Bases yes, exponents no: 1 ≡ 6 (mod 5), but (−1)¹ = −1 while (−1)⁶ = 1. You cannot reduce an exponent mod n.

Division means multiplying by an inverse

Mod 6, 3x ≡ 3 has the solution x = 3, so you cannot just cancel the 3s. Cancelling needs a multiplicative inverse, which exists exactly when a and n are coprime.

inverse.py 
from math import gcd

if gcd(7, 30) == 1:
    inv = pow(7, -1, 30)
    x = 14 * inv % 30
    print(inv, x)  # 13 2

Fermat's little theorem in three steps

Fermat's little theorem: for prime p not dividing a, a^(p−1) ≡ 1 (mod p).

1
List the multiples

Take a, 2a, …, (p−1)a. None is 0 mod p, and no two match: ia ≡ ja lets you cancel a, giving i = j.

2
They are a shuffle

So mod p they are exactly 1, 2, …, p−1 in some order. Multiply all of them: a^(p−1) · (p−1)! ≡ (p−1)!.

3
Cancel the factorial

(p−1)! is coprime to p, so it has an inverse. Cancel it: a^(p−1) ≡ 1. Example: 7⁹⁵ ≡ 7¹¹ ≡ 2 (mod 13).
