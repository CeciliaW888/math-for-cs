Day 20: Independence

Hash functions, noisy channels and randomized algorithms all quietly assume that some events are independent. Today we pin that word down, and then meet the birthday paradox, which decides how long a hash has to be.

The bookmaker test

💡
Picture a bookmaker taking bets on A. News arrives that B happened. If the odds on A don't move, B was irrelevant to A, and the two are independent. In symbols, Pr[A | B] = Pr[A], or Pr[B] = 0.
✓
Monty Hall: independent

You pick door 1, and door 2 is opened and shown empty. Pr[door 1 has the prize | that reveal] = 1/3 = Pr[door 1 has the prize]. The reveal tells you nothing about your own door.

✗
Disjoint: dependent

If B happened, then A certainly did not: Pr[A | B] = 0 ≠ Pr[A], unless one of the events has probability 0.

✗
Nested: dependent

If B ⊆ A, then Pr[A | B] = 1, which differs from Pr[A] unless A is certain.

Proof: the product rule is equivalent

Theorem: A is independent of B if and only if Pr[A ∩ B] = Pr[A] · Pr[B].

1
Case Pr[B] = 0

A and B are independent by definition. By monotonicity, 0 ≤ Pr[A ∩ B] ≤ Pr[B] = 0, so both sides of the product rule equal 0.

2
Case Pr[B] ≠ 0

Independence says Pr[A ∩ B] / Pr[B] = Pr[A]. Pr[B] is not 0, so we can multiply both sides by it.

3
Conclude

Pr[A ∩ B] = Pr[A]·Pr[B], and every step reverses. The product form is symmetric, so independence is a symmetric relation.

Pairwise is not mutual

Pairwise independence checks only pairs. Mutual independence demands the product rule for every sub-collection. The forensic claim that "9 markers at 10% each gives 1 in a billion" needs the mutual version.

The birthday paradox

The birthday paradox: with 365 days, only 23 people give better-than-even odds of a shared birthday. Using 1 − x ≤ e−x, Pr[no match] ≤ e−n(n−1)/(2d), so n ≈ √(2 ln 2 · d) ≈ 1.18√d.

birthdays.py 
def p_no_match(n, d=365):
    p = 1.0
    for i in range(n):
        p *= (d - i) / d
    return p

exact = 1 - p_no_match(23)          # 0.5072972
estimate = 1 - math.exp(-23 * 22 / (2 * 365))  # 0.5000018
Compute the chance that n people all have different birthdays, assuming d equally likely days.
Start at certainty, then add people one at a time.
Person i must avoid the i days already taken. Birthdays are independent, so the factors multiply.
This is the generalized product rule from the counting unit, divided by dn.
Return the no-match probability.
With 23 people, a match is already slightly more likely than not.
The e−x shortcut lands very close, and always a little below the exact value.
ℹ️
Why CS cares: collisions show up after about √d random items. A hash or signature space therefore has to be roughly the square of the number of files or messages you expect to handle. For 32-bit hashes, a collision becomes likely after only about 77,000 files.

Ten heads in a row: what next?

Ten heads in a row! Tails is definitely due now.
A fair coin has no memory. The flips are independent, so the next one is heads with probability 1/2.
Hmm, maybe this coin is two-headed. Ten heads is a 1-in-1024 event for a fair coin.
Law of total probability: Pr[H | H¹⁰] = 1·Pr[cheat | H¹⁰] + ½·Pr[fair | H¹⁰]. If cheating is possible, the answer is above 1/2.
So the gambler is wrong both ways. Tails is never more likely than 1/2.
